## P1 佐藤 美咲 — 自分の日常着を買う一般の購入者（優先度 1）

| 項目 | 内容 |
|------|------|
| 属性 | 30 代、会社員 |
| 使う場面 | 通勤中や昼休みにスマートフォンで、仕事にも休日にも着られるベーシックな服を探す |
| 目的 | 欲しい色とサイズの服を、迷わず数分で注文する |
| 困りごと | 色やサイズを選び忘れたままカートに入れてしまう。注文の最後で入力ミスに気づき、最初からやり直す |
| 主に使う画面 | 商品一覧、商品詳細、カート、注文手続き、注文完了（購入の流れ全体） |

## P2 田中 健太 — 子ども服をまとめて買う親（優先度 2）

| 項目 | 内容 |
|------|------|
| 属性 | 40 代、子ども 2 人の親 |
| 使う場面 | 週末に自宅の PC で、成長に合わせて子ども服をサイズ違いでまとめて買う |
| 目的 | キッズの商品だけを見て、きょうだいそれぞれのサイズを 1 回の注文で買う |
| 困りごと | 大人用の商品に埋もれてキッズの商品が探しにくい。同じ服をサイズ違いで買うと、カートで数量や内訳が分かりにくくなる |
| 主に使う画面 | 商品一覧（キッズの絞り込み）、商品詳細（サイズ選択）、カート（数量変更・削除） |

## Relationships and Priority

- 購入の流れ全体は P1 を基準に設計し、P2 は「カテゴリの絞り込み」と「同じ商品を複数サイズで買うカート操作」の確認に使う。
- P2 のために、キッズ商品のサイズは 110 / 120 / 130 / 140（cm）とする。`requirements.md` の前提（全商品 S / M / L / XL）からの変更なので、承認ゲートで確認する。

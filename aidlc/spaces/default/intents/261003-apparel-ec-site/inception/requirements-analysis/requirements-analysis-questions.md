# Requirements Analysis — Questions

> Stage: requirements-analysis（Inception 2.3）· Scope: workshop · Depth: Minimal · Test Strategy: Minimal
> 元の依頼: 「ユニクロのような自社のECサイトを構築したいです」
> 今回のゴール（プラン B）: 1 時間以内に、**ローカルで動く画面だけのモックアップ**を作る（要件分析 → ユーザーストーリー → 画面設計 → コード生成 → ビルドとテスト）。
> チームの進め方（`team-practices.md`）: Minimal テスト、workshop では実デプロイしない、フォーマッタとリンタを設定する、秘密情報をハードコードしない、カード情報を自社で保存しない。
>
> アーキテクチャ設計のステージを省くため、技術の選択もここで決めます。

---

## Q1. モックアップで動かす画面の範囲（select all that apply）

モックアップでクリックして動かせるようにする画面を選んでください。選んだ数が多いほど、コード生成に時間がかかります。

A. 商品一覧（カテゴリ別：メンズ／ウィメンズ／キッズ などで絞り込み）
B. 商品詳細（サイズ・カラーを選んでカートに入れる）
C. カート（数量変更、削除、合計金額の表示）
D. 注文手続き〜注文完了（配送先の入力、ダミーの支払い。本物の決済はしない）
E. 会員ログイン・マイページ（ダミーのログイン）
X. Other (please specify)

[Answer]:A, B, C, D

## Q2. 技術スタック

モックアップを作る技術を選んでください。この Mac には Node v24 が入っています。

A. React + Vite + TypeScript — 画面だけの構成で、起動が速くシンプル。後から本番化するときは API を別に作る（推奨）
B. Next.js（App Router）+ TypeScript — サーバー機能込みのフレームワーク。将来そのまま本番化しやすいが、構成が少し重い
C. HTML / CSS / JavaScript のみ — ビルド不要で一番軽いが、画面が増えると保守しにくい
X. Other (please specify)

[Answer]:A

## Q3. データの持ち方

商品データとカートの中身をどこに持つかを選んでください。

A. 商品はダミーの JSON をアプリに同梱し、カートはブラウザ（localStorage）に保存する。サーバーは立てない（推奨。最短で動く）
B. 上に加えて、簡易なモック API（MSW など）を立て、画面から API 経由で取得する（後で本物の API に差し替えやすいが、時間が少し増える）
X. Other (please specify)

[Answer]:A
